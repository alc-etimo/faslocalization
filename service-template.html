Case study 02 · Timed subtitle translation

Translate the timed file. Keep the dialogue alive — and the subtitles readable.

The English file already arrives with cue timing. The work is translating each cue into Brazilian Portuguese that sounds like a person, inside the brief's reading speed and line length.

EN → PT-BR Timed SRT input Brief-driven CPS / CPL Illustrative data

The timing is already there. The dialogue is not.

A timed subtitle file carries cue in/out values, line breaks and reading speed on the source side. Translation is not the same as spotting — it is fitting the target language into a frame that was decided by someone else, without breaking it.

This case demonstrates the translation step in a subtitle editor mock: source cues, editable target cues, live CPS and CPL, and a delivery profile that decides whether the cue is ready or not.

What the translation step shows.

Natural Brazilian Portuguese. “I thought you were leaving” is not “Eu pensei que você estava indo.” The demo target uses a real pt-BR phrasing that fits the tone and the frame.

Line breaks chosen, not inherited. Insert or remove a break and the CPS, CPL and line-count values update live.

Reading speed that follows the cue. Change the duration and the metrics change — a shorter cue demands a tighter line, not the same text squeezed.

A brief, not a guess. Switching the profile changes what “valid” means. Nothing in this demo is presented as a universal subtitling standard.
